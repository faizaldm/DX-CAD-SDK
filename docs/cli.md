# The command line

`dxcad` is the widest door into DX-CAD: every operation the kernel has is
reachable from it, no window is opened unless one is asked for, and every
command reads and writes plain files. This page has one section per
subcommand, in the order `dxcad --help` lists them, and each says what the
command is for, what it takes, what it writes, every option it has and what
it exits with. Each section closes with the command's usage line and its
arguments, generated from the command itself by
`python -m dxcad.docsgen cli`, so that part can never say other than what
`--help` does.

Three statuses are used throughout, and they are the same in every command:

- `0`, the command did what it was asked.
- `1`, `cli.UNSOUND`: nothing was wrong with the command line, and the answer
  is no. Only `validate`, `printability` and `doctor` give it.
- `2`, `cli.USAGE_ERROR`: the command line, or a file it named, was wrong.
  Nothing is written and a line saying what went wrong goes to stderr.

A model that fails is a usage error too: the model's own traceback is turned
into one line naming the model and the line in it that raised, never a
traceback of DX-CAD's own.

### The worked commands

Every section gives a command that can be pasted as it stands. They run
in the order they are written, in one empty directory, and the test suite
runs them there at every commit, so a command on this page is a command that
works. These two come first and make the part the rest of them read:

Worked, exits 0:

```
dxcad examples bracket
dxcad run bracket.py --output bracket.dxcprt
```

## info

What a project holds, in three columns: one line per entry with its name, its
volume and whether it is a valid solid, then a last line naming the model the
project carries and how long it is.

Takes a `.dxcprt` or `.dxcasm` project (an older `.dxcad` too), a `.py` model to run first, or `-` for a model on
standard input. Writes nothing but its own output.

- `--timeout SECONDS` stops a model that runs longer than this. No limit by
  default, and it is the same option, with the same meaning, wherever a
  command can be given a model.

Exits `0`, or `2` when the file is not a project and not a model.

Worked, exits 0:

```
dxcad info bracket.dxcprt
```

## validate

Whether every entry is a sound solid, and with `--script` whether the shapes
in the file still agree with the model that is supposed to build them. It
prints nothing when all is well, which is what a build step wants.

Takes what `info` takes. Writes nothing.

- `--script` re-runs the model the project carries and compares what it
  builds with what is stored.
- `--tolerance TOLERANCE` is how far a volume may differ from the model's,
  relative; 1e-06 by default.
- `--timeout SECONDS`, as everywhere.

Exits `0` when sound, `1` when a solid is invalid or a volume disagrees, and
`2` when the file cannot be read or the tolerance is not a number.

Worked, exits 0:

```
dxcad validate bracket.dxcprt --script
```

<!-- generated by python -m dxcad.docsgen cli: validate -->


- `project`: a .dxcprt or .dxcasm file, or a .py model to run, or - for a model on standard input
- `--script`: also check the entries against the model.py the project carries
- `--tolerance TOLERANCE`: how far a volume may differ from the model's, relative; 1e-06 by default
- `--timeout SECONDS`: stop a model that runs longer than this; no limit by default

## describe

Everything an agent needs to reason about a part without seeing it: per entry
the volume and area, the bounds and size, the centre of mass, the faces by
the kind of surface under them, the edges and vertices, and every round hole
with its diameter, depth, axis and centre.

Takes what `info` takes. Writes nothing but its own output.

- `--name NAME` describes that one entry; every entry by default, and a name
  the project does not have is a usage error.
- `--json` prints the same facts as one JSON document, numbers unrounded,
  which is the form to pipe into something else.
- `--timeout SECONDS`, as everywhere.

Exits `0`, or `2` when the file cannot be read or the name is not there. An
entry that is an unsound solid is said to be invalid and still exits `0`.

Worked, exits 0:

```
dxcad describe bracket.dxcprt
```

- `project`: a .dxcprt or .dxcasm file, or a .py model to run, or - for a model on standard input
- `--name NAME`: the one entry to describe; every entry by default
- `--json`: print the same facts as one JSON document, numbers unrounded
- `--timeout SECONDS`: stop a model that runs longer than this; no limit by default

## serve

The agent door: an MCP server on standard input and output, one JSON-RPC
message a line, holding one document of named parts. It is what
[agents.md](agents.md) is about, and every tool it offers is listed there.

Takes no file: the client speaks to it down a pipe. Writes only what a tool
is asked to write, and only inside its directory.

- `--directory DIR` is the directory the tools' paths are taken from and the
  only place the server may read or write. The directory it was started in by
  default, which is not somewhere a client chooses carefully.
- `--allow-run` offers the two tools that exec a model.py with the user's own
  permissions. Without it the server has neither of them.
- `--config` starts no server and prints the JSON an MCP client is configured
  with, naming this Python and this directory. On stderr it names the file
  `--install` would write.
- `--install` starts no server either: it writes what `--config` prints into
  Claude Desktop's configuration file. On Windows that is the Microsoft Store
  edition's, under
  `%LOCALAPPDATA%\Packages\Claude_*\LocalCache\Roaming\Claude`, when that
  edition is installed, and otherwise the one under `%APPDATA%\Claude`. On
  macOS it is under `~/Library/Application Support/Claude`, and elsewhere
  under `~/.config/Claude`. It keeps every other key the file holds, its
  other servers and its preferences alike, and copies the old file beside it
  with `.bak` added. It prints the path it wrote, and on stderr the backup's
  name. `--directory` and `--allow-run` go into the entry. A dxcad entry
  already there is replaced only with `--force`, and a file that is not JSON
  is left alone; either exits `1`.
- `--config-file FILE` is the file `--install` writes instead of Claude
  Desktop's own.
- `--force` lets `--install` replace a dxcad entry.
- `--http` serves the same tools over HTTP instead, on 127.0.0.1 only, at
  `http://127.0.0.1:PORT/mcp`: a JSON-RPC message is POSTed and answered as
  JSON. Every request carries `Authorization: Bearer TOKEN`, TOKEN being what
  `DXCAD_TOKEN` holds or one printed on stderr at start; without it, or with
  another, the answer is 401. The two tools that run Python need
  `--allow-run-http` as well as `--allow-run`.
- `--port PORT` is the port `--http` listens on; 8765 by default.
- `--allow-run-http`, with `--allow-run`, offers the run tools over HTTP.
- `--window [CHANNEL]` drives the open DX-CAD window instead of a document of
  the server's own: every tool call is carried out on the window's document,
  one undo step each, and the window's model.py in its pane gains the
  statement for it, as a window action writes one: for the tools that make,
  move, drill, round or chamfer a part, the booleans, the patterns, the two
  sketch tools, and renaming, copying or removing a part. The first call
  takes the template's place, and undoing it puts the template back. For any
  other tool (hollow, the sheet metal tools, an import) the status bar says
  the model has no line for it and the part stays. A relative path a tool
  writes to is taken from the window's document folder when the document has
  been saved, else from `--directory`, else from the user's Documents folder;
  the answer gives the whole path as `written`, and the window's status bar
  says where the file went. A window that closes lets the server go on: while
  no window is open each tool call is refused saying so, and the next window
  that listens on the channel is found by the next call, with no restart. The
  window listens on a named pipe on Windows
  and a Unix socket elsewhere, never a network port, this user's channel
  unless CHANNEL names another. `--allow-run` still gates the two tools that
  run Python.

Exits `0` at the end of input, `1` when `--window` finds no window
listening, or `2` when the directory is not there.

Not run by the test: a server waits on standard input, so it would never
return; [examples/bracket.md](examples/bracket.md) drives one from a file
instead.

```
dxcad serve --directory .
```

- `--directory DIR`: work in DIR: the tools' relative paths are taken from it, since the client that starts the server chooses where and cannot be told

- `--port PORT`: the port --http listens on; 8765 by default
- `--allow-run-http`: with --allow-run, offer the two tools that run Python over HTTP too
- `--force`: let --install replace a dxcad entry the configuration already has

## printability

Whether each entry will print on a desktop printer: per entry the volume and
the mass in the material given, the centre of mass, how many faces overhang
further than the printer can manage and their area, the thinnest wall and
where it is, and a warning for each check that fails.

Takes what `info` takes. Writes nothing but its own output.

- `--material MATERIAL` is the filament, one of PLA (1.24 g/cm3), PETG
  (1.27), ABS (1.04), ASA (1.07) and TPU (1.21), in any case; PLA by default.
  The mass line names the material and density it assumed.
- `--density DENSITY` is the density in g/cm3 of a filament not in that list,
  instead of `--material`.
- `--min-wall MIN_WALL` is the thinnest wall in millimetres that prints; 0.8
  by default.
- `--angle ANGLE` is the steepest overhang, in degrees below the horizontal,
  that prints without support; 45 by default, and it must lie strictly
  between 0 and 90.
- `--json` prints the same reports as one JSON document, numbers unrounded.
- `--timeout SECONDS`, as everywhere.

Exits `0` when no entry has a warning, `1` when any has, and `2` when the file
cannot be read, holds no entries, or an option is not a number it takes.

Worked, exits 0:

```
dxcad printability bracket.dxcprt
```

<!-- generated by python -m dxcad.docsgen cli: printability -->

```text
usage: dxcad printability [-h] [--material MATERIAL | --density DENSITY] [--min-wall MIN_WALL]
                          [--angle ANGLE] [--json] [--timeout SECONDS]
                          project
```

- `project`: a .dxcprt or .dxcasm file, or a .py model to run, or - for a model on standard input
- `--material MATERIAL`: the filament, one of PLA, PETG, ABS, ASA, TPU, mild steel, stainless 304, aluminium 5052, galvanised steel; PLA by default
- `--density DENSITY`: the material's density in g/cm3, for a filament not in that list
- `--min-wall MIN_WALL`: the thinnest wall in mm that prints; 0.8 by default
- `--angle ANGLE`: the steepest overhang in degrees below the horizontal that prints; 45.0 by default
- `--json`: print the same reports as one JSON document, numbers unrounded
- `--timeout SECONDS`: stop a model that runs longer than this; no limit by default

## bom

A bill of materials: parts a model put in with `place()` from one source, as
one shape, are one line with a count, and every other part is a line of its
own. Each line gives its name (the start its parts' names share, so `bolt_1`
to `bolt_4` are `bolt`), how many, one part's volume, its mass when a material
or a density is given, one part's size before it was placed, and the file
it came from when it was placed from one or taken from another project with
`use()` (item 576), as `from bracket.dxcprt:bracket`.

Takes what `info` takes. Writes nothing but its own output.

- `--material MATERIAL` gives each line's mass in that filament, one of those
  `printability` takes.
- `--density DENSITY` gives each line's mass at that density in g/cm3,
  instead of `--material`.
- `--csv` prints the bill as CSV with a header row: name, count, volume,
  mass, size_x, size_y, size_z, the parts, joined by `;`, and the source file.
- `--flat` totals each part over the whole assembly. Without it an assembly
  holding sub-assemblies (`use(path, as_group=True)`, item 577) is printed as
  a tree, each sub-assembly a line naming its file with its own bill set in
  under it, the counts multiplied down it.
- `--timeout SECONDS`, as everywhere.

Exits `0`, and `2` when the file cannot be read or holds no entries.

Worked, exits 0:

```
dxcad bom bracket.dxcprt --csv
```

<!-- generated by python -m dxcad.docsgen cli: bom -->

```text
usage: dxcad bom [-h]
                 [--material MATERIAL | --density DENSITY | --default-material DEFAULT_MATERIAL]
                 [--csv] [--columns KEYS] [--each] [--flat] [--timeout SECONDS]
                 project
```

- `project`: a .dxcprt or .dxcasm file, or a .py model to run, or - for a model on standard input
- `--material MATERIAL`: give each line's mass in this filament, one of PLA, PETG, ABS, ASA, TPU, mild steel, stainless 304, aluminium 5052, galvanised steel
- `--density DENSITY`: give each line's mass at this density in g/cm3
- `--default-material DEFAULT_MATERIAL`: take each part with no material of its own to be made of this, marked (default), as the window's Default material does
- `--csv`: print the bill as CSV, with a header row
- `--columns KEYS`: print the bill as CSV in a drawing's parts list columns, comma-separated, of item, part_number, description, material, qty, rev, size and mass
- `--each`: list every part on a line of its own, rather than identical parts as one
- `--flat`: total each part over the whole assembly rather than listing sub-assemblies as a tree
- `--timeout SECONDS`: stop a model that runs longer than this; no limit by default

part keeps a stable id through renames, so an assembly using it by an old
name still finds it.

Writes nothing but its own output.

Exits `0`, or `2` for a part file or a folder that is not there.

## interference

Whether any two parts clash: for every pair, in document order, `overlap`
with the volume they share and its bounding box, `touching` when they meet
but share no volume (a face against a face), or `clear`.

Takes what `info` takes. Writes nothing but its own output.

- `--name NAME` checks only the pairs among the parts named, one `--name`
  each; every part by default.
- `--json` prints the pairs as one JSON document, with how many overlap.
- `--timeout SECONDS`, as everywhere.

Exits `0` when no pair overlaps, `1` when any does, and `2` when the file
cannot be read or names no such part.

Worked, exits 0:

```
dxcad interference bracket.dxcprt
```

## render

A picture of the parts as a PNG, drawn by OCCT with no window on screen: the
picture the agent door's `render_view` tool answers for the same request,
byte for byte.

Takes what `info` takes and the `.png` file to write.

- `--name NAME` draws only the parts named, one `--name` each; every part by
  default.
- `--view {front,back,left,right,top,bottom,isometric}`; isometric by default.
- `--mode {shaded_edges,shaded,wireframe,translucent}`, the window's display
  modes; shaded_edges by default.
- `--width WIDTH` and `--height HEIGHT` in pixels, each 1 to 2048; 800 by 600
  by default.
- `--explode FACTOR` draws the parts moved apart, as `export --explode` writes
  them.
- `--timeout SECONDS`, as everywhere.

Exits `0`, `1` when this machine cannot draw, and `2` when the file cannot be
read, names no such part or a size is out of range.

Not run by the test: drawing with no window is built for Windows only so far,
and the page's commands are run on every platform the suite is.

## export

One entry, or all of them, written out for a slicer, a mesher or another CAD.

Takes a project and the file to write, which ends in `.step`, `.stl`,
`.3mf` or `.brep`; with `--all`, a directory instead. Writes that file, or one file per
entry in that directory.

A file ending `.dxf` or `.svg` is a drawing instead: the Sketches the model
(or the project's model) names at its top level, one layer or group each,
named as the model names them, in millimetres, with lines, arcs, circles,
ellipses and splines each written as themselves. A model that makes only
sketches, and registers no part, draws as well as any.

- `--name NAME` is the entry to write; the first entry by default. For a
  drawing it is the one sketch to draw, every sketch by default.
- `--all` writes every entry into the output directory, one file each, or
  with a drawing format every sketch, one file each.
- `--format {3mf,brep,dxf,step,stl,svg}` is the format `--all` writes; step by
  default.
- `--explode FACTOR` writes each part moved apart as an exploded view of the
  whole project shows it: away from the assembly's centre of mass along the
  line to the part's own, FACTOR times that distance; 0 is assembled. Not for
  a drawing.
- `--timeout SECONDS`, as everywhere.

Exits `0`, or `2` when the project cannot be read, the name is not there or
the suffix names no format DX-CAD writes.

Worked, exits 0:

```
dxcad export bracket.dxcprt bracket.step
```

## drawing

Given a `.dxcdrg`, a drawing saved from the window (items 572 and 682; an older `.dxcaddrg` too), it draws that
drawing from its project as the project is now, with its own sheet, views,
scale and fields, and writes what the window's Export Drawing writes; the
file to write may follow it, `dxcad drawing part.dxcdrg part.pdf`. A
project that is gone is named by its path, and exits `2`.

Otherwise, a drawing sheet of a project's parts: the front, top, right and isometric
views, visible edges solid and hidden ones dashed, at one standard scale that
fits every view in its quarter of the drawing area, inside the title block,
with the bill of materials as a parts list. The views are fitted first: a
list longer than one column of the sheet takes a second column beside them
only where they keep their scale, and runs on to further sheets, the same
title block numbered on, where they would not. Written as a DXF (AutoCAD 2000,
one layer per view's visible and hidden edges) and as a one-page PDF the size
of the sheet. The title block states the scale and the sheet size and names
the project, its file and the date. The front, top and right views carry
their overall width and height, and every drilled hole a diameter callout
where it is seen round, with its depth when it is blind, each a DIMENSION in
the DXF; none is put over a view, and one that would be is stacked further
out. This is a draft a person finishes, not a toleranced drawing.

Takes a project or a model.py. Writes PROJECT-drawing.dxf and
PROJECT-drawing.pdf beside it, or the files named.

- `--output PATH` is a file to write, ending `.dxf` or `.pdf`; give it twice
  for both.
- `--sheet NAME` is the sheet: A4, A3, A2 or A1, landscape on the default
  title block, or one of ten ready sheets (item 571): ISO 5457 `ISO-A4-portrait`,
  `ISO-A4`, `ISO-A3`, `ISO-A2`, `ISO-A1` and `ISO-A0` with an ISO 7200 title
  block, and ASME Y14.1 `ANSI-A`, `ANSI-B`, `ANSI-C` and `ANSI-D` with an ANSI
  one, each with the Designmatix logo; on those the scale is the largest of
  5:1, 2:1, 1:1, 1:2, 1:5, 1:10 and 1:20 that fits. A3 by default; any other
  name is refused, listing them. Their fields a person fills are
  `company_name`, `drawn_by`, `checked_by`, `material`, `finish`,
  `tolerance`, `drawing_no` and `rev_number`.
- `--font NAME` letters the sheet in a TrueType font of the system's, by its
  file's name (`arial`) or a `.ttf` path: named in the DXF's STYLE table and
  embedded in the PDF. The bundled DejaVuSans by default; a named font this
  machine lacks is replaced by it, with a warning naming both.
- `--text-height MM` is the height of the dimensions, the view labels and the
  title block's fields: 2.5, 3.5, 5 or 7.
- `--field NAME=VALUE` fills a field the title block names, such as
  `customer_name` or `project_name`; it may be given again for another. Fields
  nobody fills are left empty.
- `--force` writes over a file that is already there.
- `--timeout SECONDS`, as everywhere.

Exits `0`, `1` when the sheet cannot be made, or `2` when the project cannot
be read, a file is in the way or a suffix is neither `.dxf` nor `.pdf`.

Worked, exits 0:

```
dxcad drawing bracket.dxcprt --sheet A4 --field customer_name=ACME
```

## flat

The flat pattern of a sheet part, as a DXF for a laser or a plasma table:
the outline to cut on layer CUT, each round hole a circle on CUT, each
rectangular cutout a closed polyline on CUT, each bend's two lines on layer BEND and a note beside each bend on layer NOTES,
such as `UP 90 R2`. The project's
model.py is re-run, as `rebuild` runs it, and the pattern is worked out from
what the model built the part from: its base profile, its flanges, and the
thickness, bend radius and K-factor of its `SheetSpec`. Prints the file
written, then the flat's size and bend count, such as
`124.524 x 50.000 mm, 1 bend`, with its hole count after them when it has
holes: `124.524 x 50.000 mm, 1 bend, 1 hole`, and its cutout count last
when it has cutouts, the base's and its flanges' together:
`124.524 x 50.000 mm, 1 bend, 1 cutout`.

Takes a project carrying a model.py. Writes NAME-flat.dxf beside it, or the
file named.

- `--part NAME` is the sheet part to unfold, one the model registers with
  `part` from `base_flange` and `flange`.
- `--output PATH` is the .dxf file to write, or a .svg: an SVG in
  millimetres, +y up, with the outline and each cutout as a closed path,
  holes as circles, bend lines dashed and each bend's note as text; or a .step or .stp: the
  flat as one solid, the outline extruded by the sheet's thickness from
  z = 0 with every hole and cutout cut through it, for a CAM program that wants a
  solid. Any other name is written as DXF.
- `--all` unfolds every sheet part the model registers instead, each to
  NAME-flat.dxf beside the project, in the model's order, printing one line
  for each: its path, then its size and bend count after a colon. It takes
  no `--part` and no `--output`.
- `--title` writes the part's name and the sheet's thickness, such as
  `tray, 2 mm`, once below the flat on the DXF (a TEXT on layer NOTES) or
  the SVG (a text), so the cut part can be told apart on the shop floor.
  With `--all`, each part's own name. A .step or .stp output ignores it.
- `--bend-zones` also draws the two edges of each bend zone, continuous, on
  layer BEND-ZONE (a class of its own in the SVG), beside the one dashed
  centre line on BEND that every flat has, for a shop that wants them.
  Without it every byte is as before.
- `--edges` prints, straight after the size line, one line per edge of the
  part's outline, numbered from 0 as `flange()` takes them: its two ends,
  its length and the flange on it with its leg, or `free`, such as
  `edge 1: (100, 0) to (100, 50), 50.000 mm, flange UP 90 R2 20.000 mm`.
  With `--all`, each part's edge lines follow its own line. Without it the
  output is as above.
- `--bends` prints a bend table for the press brake after the size line
  and any edge lines,
  one line per bend in the flat's order: its direction, angle and inside
  radius, its bend allowance worked with that radius, and the length of its
  bend lines, such as `bend 1: UP 90 R2, allowance 4.524 mm, length 50.000 mm`.
  With `--all`, each part's bend lines follow its own line. Without it the
  output is as above.
- `--cut` prints, after the size line and any bend lines, the flat's cut
  length, the outline's perimeter plus every hole's circumference and
  every cutout's perimeter, and its area, the outline's less every hole and
  cutout, for quoting a laser or a plasma table, such as
  `cut length 349.048 mm, area 6226.195 mm²`, then a line with the flat's
  mass, its area times the thickness at its sheet's metal, and the metal,
  such as `mass 97.751 g, mild steel`. With `--all`, each part's lines
  follow its own lines. Without it the output is as above.

A shop's CAM software may want a different DXF. `--profile NAME` writes it
as a shop export profile has it: the DXF version (R12, R2000, R2013 or
R2018), the units (mm or inch), the names of the cut, bend and notes layers,
each bend as its dashed centre line or its two zone edges, holes as circles
or as polylines within a chord tolerance, notes on or off, and a colour for
each layer. Profiles are kept in DX-CAD's settings; `Default` is the plain
output above, byte for byte, and is what is written without `--profile`.
`--profiles` lists them, one line each. A profile applies to a DXF; an SVG or
STEP is written as ever. An unknown profile is refused, listing the names.

Exits `0`, or `2` when the project cannot be read or carries no model.py,
the model fails, it builds no part of that name, the part is not a sheet
part, neither `--part` nor `--all` is given, `--all` comes with `--part` or
`--output`, or `--all` finds no sheet part. With `--all`, a sheet part that
cannot be unfolded is said on stderr, the others are still written, and the
exit is `1`. The bracket is not a sheet part:

Worked, exits 2:

```

```

Takes nothing. Writes `dxcad.spec` and prints it, then the PyInstaller

- `--output OUTPUT` is the directory to write the spec into; the working

- `--appdir DIR` lays DIR, the directory a Linux freeze collected, out as

  build job does (item 643). An AppDir already there, or a DIR with no
  `DX-CAD` executable, is refused. The macOS spec's bundle carries
  `Info.plist` (bundle id `uk.co.designmatix.dxcad`, the version) and the
  `.icns` icon, and CI packs `DX-CAD.app` into `DX-CAD-<version>-macos.dmg`.

  freeze collected, into the output directory instead, with Inno Setup 6's
  ISCC found on PATH or in its default install folder, and prints its path,
  `DX-CAD-<version>-windows-x64-setup.exe`. Without Inno Setup it says so,
  naming it, and builds nothing. Windows only. The installer script is the
  one the package carries as `dxcad/installer/dxcad.iss`, so this works from
  a pip install, else a checkout's `installer/dxcad.iss`; it says which.
- `--sign`, with `--installer`, signs the build with `installer/sign.ps1`
  through PowerShell. The executables in DIR (`DX-CAD.exe`, `dxcad.exe`, and
  `dxcad-gui.exe` where there is one) are signed before Inno Setup packs them.
  Then Inno Setup signs the uninstaller and the installer with the same script
  as it builds them. The certificate is the one `DXCAD_SIGN_THUMBPRINT` names,
  and the timestamp server is `DXCAD_SIGN_TIMESTAMP` (`http://ts.ssl.com` by
  default). Without the script, the variable or PowerShell, it says why and
  builds the installer unsigned.
- `--release DIR` makes the signed Windows release of DIR into the output
  directory, every step in order: signs the executables, builds the installer
  and has Inno Setup sign it, packs the zip, reads back every signature with
  `installer/verify.ps1`, and prints the installer's and the zip's paths and a
  table of files, statuses and signers. Without Inno Setup, the signing script
  or `DXCAD_SIGN_THUMBPRINT` it is refused, saying why. Not with `--pack` or
  `--installer`.

Exits `0`, `1` when ISCC, the signing or a signature fails, when a release
cannot be signed or built, or when `--pack` finds an unsigned executable, or
`2` when a directory it is given is not there or `--appdir` refuses it, the installer or the release is
asked for another platform, `--sign` is given without `--installer`, or
`--release` with `--pack` or `--installer`.

The Windows zip is what a GitHub release carries for someone without Python:
they download `DX-CAD-<version>-windows-x64.zip`, unzip it anywhere, run
`DX-CAD.exe` from the `DX-CAD` folder, and run `dxcad.exe doctor` there to
tell that it works.

Not run by the test: the Windows spec is frozen by the suite through the
release checklist's freeze step instead, and the macOS and Linux builds are
made on machines this suite never sees.

```
dxcad freeze --platform linux
```
